XXE Injection — Secure

External entity processing is disabled. Any XXE, SSRF, or XInclude payload is detected and rejected before parsing begins.

What Was Fixed

The vulnerable version read local files and simulated SSRF whenever a SYSTEM or XInclude directive appeared in the XML body. This version scans every incoming XML payload for dangerous patterns (DOCTYPE, ENTITY, SYSTEM, xi:include, file://, http://169.254) and rejects the request immediately with an HTTP 400 — no file system access or outbound requests are made.

All payloads below will be blocked — try them to see the security response.

Lab 1 – File Read via XXE (Blocked)

The server rejects any XML containing a DOCTYPE or SYSTEM declaration. File contents are never read.

Try this payload — it will be blocked:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///C:/Windows/System32/drivers/etc/hosts">
]>
<user><name>&xxe;</name></user>

Lab 2 – SSRF via XXE (Blocked)

HTTP-based SYSTEM entities (including AWS EC2 metadata URLs) are rejected. The server makes no outbound requests from user-supplied XML.

Try this payload — it will be blocked:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "http://169.254.169.254/">
]>
<stockCheck><productId>&xxe;</productId></stockCheck>

Lab 3 – XInclude Attack (Blocked)

xi:include directives are detected by namespace scan and rejected. XInclude processing is completely disabled server-side.

Try this payload — it will be blocked:

<foo xmlns:xi="http://www.w3.org/2001/XInclude">
  <xi:include href="file:///C:/Windows/win.ini" parse="text"/>
</foo>
